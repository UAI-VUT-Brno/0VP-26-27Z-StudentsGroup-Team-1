# Repository rules

## Branches

- The agent creates `feat/t1-<issue_number>-<short-slug>` from the base branch, for example `feat/t1-50-add-task-count-endpoint`.
- Never commit to `main` or to the base branch directly.

## Commits

- Conventional Commits with a scope: `<type>(<scope>): <summary>`.
  - **Type:** `feat`, `fix`, `test`, `docs`, `refactor`, `style`, `chore`.
  - **Scope:** the layer or area the commit touches:

    | Scope | Files |
    |---|---|
    | `dto` | `src/UAI.ZeroVP.DTO` |
    | `data` | `src/UAI.ZeroVP.Data` |
    | `api` | `src/UAI.ZeroVP.API` |
    | `mcp` | `src/UAI.ZeroVP.API/Mcp` |
    | `openapi` | OpenAPI transformers and their tests |
    | `docker` | `Dockerfile`, compose files |

    Tests take the scope of the layer they test: `test(data):`, `test(api):`. Never use `test(tests)`.
    Docs and whitespace fixes take the scope of the area they touch: `docs(api):`, `docs(mcp):`, `style(data):`. Never use a commit without a scope, such as `docs:` or `style:`.
  - **Summary:** imperative, lower case, no full stop, at most 72 characters. Example: `feat(api): add GET /api/todos/count endpoint`.
- **Every commit must build.** If a change in one layer breaks a caller in another layer (for example, a new parameter in `ITodoRepository`), fix the caller in the same commit.
- One logical step per commit. Usual order: DTO → Data (with its tests) → API (with its tests) → docs.
- Stage files by name (`git add <paths>`). Never use `git add -A` or `git add .`.
- Never amend, rebase, force-push or rewrite pushed history.

## Documentation

Update the docs in the same PR when the change affects them:

| Change | Update |
|---|---|
| New or changed endpoint, request or response | `README.md` endpoint table and `docs/openapi.md` |
| New configuration key or environment variable | `README.md` and the related file in `docs/` |
| Persistence or file format | `docs/persistence.md` |
| Running several instances | `docs/multiple-instances.md` |
| MCP tools | `docs/mcp.md` |
| Docker | `docs/docker.md` |

Docs are in English, Markdown, LF line endings.

## Pull request

- Title: `[0VP-T1-NN] <issue title without the prefix>` when the issue title has a `0VP-T1-NN` prefix. `NN` is the task code from the issue title, not the issue number, and can be text: `0VP-T1-TEST Add task count endpoint` → `[0VP-T1-TEST] Add task count endpoint`. Otherwise `<type>: <issue title>`.
- Body sections, in this order:
  1. **Summary**;
  2. **Changes** (per layer);
  3. **Verification** (test counts, first-attempt result, repair cycles, `git diff --check`);
  4. the attribution line ``🤖 Generated by `/issue-to-pr` with [Claude Code](https://claude.com/claude-code)``;
  5. `Closes #<issue>` as the last line. Nothing comes after it.
- Write the body to `.issue-to-pr/<n>/pr-body.md`, never to a scratchpad or temp folder.
- Run `git diff --check <base>...HEAD` before you push. It must be clean.
- Never merge your own PR, and never close or edit the issue.

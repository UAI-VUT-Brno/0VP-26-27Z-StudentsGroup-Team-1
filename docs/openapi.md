# API documentation (OpenAPI)

**Requirement:** document every API endpoint according to OpenAPI 3.x: path and HTTP method, input parameters
with data types, all possible responses with their JSON schemas, and ideally an interactive page where the API
can be tried out.

## Summary

- The API describes itself in an **OpenAPI 3.1.1** document, generated from the code at runtime.
  There is no hand-written copy that could drift from the implementation.
- The document is served as JSON and YAML. Swagger UI on top of it lets you send requests from the browser.
- All 9 endpoints are documented, including `/health` and every error response the API can return
  (`400`, `404`, `415`, `500`, `503`).
- Automated tests check that the document is valid OpenAPI and that it matches what the API really returns.

## Where to find it

| URL | Content |
|---|---|
| `http://localhost:5258/swagger` | Swagger UI – interactive documentation, the request form is open by default |
| `http://localhost:5258/openapi/v1.json` | The OpenAPI document as JSON |
| `http://localhost:5258/openapi/v1.yaml` | The same document as YAML |

All three are enabled in the `Development` environment and disabled in `Production`.
They can be enabled with the `Swagger:Enabled` setting or the `Swagger__Enabled=true` environment variable.

To save the document to a file, for example for a client generator:

```bash
dotnet run --project src/UAI.ZeroVP.API
curl http://localhost:5258/openapi/v1.yaml -o openapi.yaml
```

## Documented endpoints

| Method | Path | Input | Responses |
|---|---|---|---|
| `GET` | `/api/todos` | query `isCompleted` (boolean, optional) | `200` list of `TodoItemDto`, `400`, `500` |
| `POST` | `/api/todos` | body `CreateTodoItemRequest` | `201` `TodoItemDto` + `Location` header, `400`, `415`, `500` |
| `POST` | `/api/todos/repeat` | body `CreateRepeatingTodoItemRequest` | `201` list of `TodoItemDto` + `Location` header of the first occurrence, `400`, `415`, `500` |
| `GET` | `/api/todos/{id}` | path `id` (uuid) | `200` `TodoItemDto`, `404`, `500` |
| `PUT` | `/api/todos/{id}` | path `id` (uuid), body `UpdateTodoItemRequest` | `200` `TodoItemDto`, `400`, `404`, `415`, `500` |
| `DELETE` | `/api/todos/{id}` | path `id` (uuid) | `204` no body, `404`, `500` |
| `POST` | `/api/todos/{id}/complete` | path `id` (uuid) | `200` `TodoItemDto`, `404`, `500` |
| `GET` | `/api/info` | – | `200` `InstanceInfoDto`, `500` |
| `GET` | `/health` | – | `200` / `503` plain text `Healthy`, `Degraded` or `Unhealthy` |

Error responses use `ProblemDetails` (RFC 9457); validation errors use `ValidationProblemDetails`
with an `errors` object. Errors returned by the controllers have the content type `application/json`,
the `500` from the exception handler has `application/problem+json`. The document lists exactly these types.

## How the document is generated

The document is generated by the built-in .NET 10 library `Microsoft.AspNetCore.OpenApi`.
It reads the controllers through ApiExplorer:

| Source in the code | Result in the document |
|---|---|
| `[HttpGet]`, `[Route]`, route constraints (`{id:guid}`) | path, method, parameter type (`string`, `format: uuid`) |
| `[ProducesResponseType]` | status codes and response schemas |
| XML `<summary>` / `<remarks>` of an action | `summary` / `description` of the operation |
| XML `<param>` / `<response code="…">` | parameter, request body and response descriptions |
| `[Required]`, `[StringLength]` on DTOs | `required`, `minLength`, `maxLength` |
| `[DefaultValue]` and XML `<example>` on DTO properties | `default` and `examples` (Swagger UI pre-fills the form with them) |
| `<summary>` of DTO properties | property descriptions; notes for developers are in `<remarks>`, which the generator ignores |

What the generator cannot read from the code is added by three transformers in `src/UAI.ZeroVP.API/OpenApi/`:

| Transformer | What it does |
|---|---|
| `HealthCheckDocumentTransformer` | Adds `GET /health`. `MapHealthChecks` does not describe its endpoint for ApiExplorer, so it would be missing. |
| `ResponsesOperationTransformer` | Removes the empty `application/json` that `[Produces]` adds to responses without a body (`204`) or with another content type (`500`), adds the `Location` header to `201` and the `X-Instance-Id` header to every response, and sorts responses by status code. |
| `AssumeUtcDateTimeSchemaTransformer` | Sets `type: string` on `firstDueAtUtc`. The property has a custom JSON converter (a value without an offset is read as UTC), and the generator leaves out the type of such properties. |

## Pitfalls for maintainers

- **JSON options.** The generator reads the minimal API JSON options (`ConfigureHttpJsonOptions`),
  not the ones from `AddControllers().AddJsonOptions(...)`. Without that the document described `priority`
  as an integer although the API sends `"High"`. `Program.cs` therefore configures both through one
  `ConfigureJson` method. Change JSON settings only there.
- **Order of `<param>` tags.** The .NET 10 XML comment generator writes every `<param>` that does not match
  an operation parameter (for example `cancellationToken`) into the request body description, and the last
  one wins. In actions with a request body, `<param name="request">` must stay after `cancellationToken`.
  `RequestBody_IsDescribedByTheRequestParameter` fails if the order changes.
  - **Custom JSON converters hide the type.** A property with `[JsonConverter]` gets a schema without `type`.
  For `DateTimeOffset?` the converter is wrapped in `NullableConverter`, so the transformer looks for the attribute,
  not for `JsonPropertyInfo.CustomConverter`. `DateWithCustomConverter_IsDocumentedAsDateTimeString` guards this.
- **`/health` is described by hand.** If its route or responses change, update `HealthCheckDocumentTransformer`.
  The tests send a request to the documented path and compare the response with the document.
- A URL that does not match any route, for example `/api/todos/abc` (not a GUID), returns `404` with
  `application/problem+json` from `UseStatusCodePages`. Such URLs are not part of the API and are not documented.

### Checklist for a new endpoint

1. XML `<summary>`, a `<param>` for every parameter and a `<response code="…">` for every status code.
2. `[ProducesResponseType]` with a type for every status code the action can return.
   `500` is declared once on the controller.
3. Add a row to `Operation_DocumentsAllResponses` and a request to `Response_MatchesDocument`
   in `tests/OpenApi/OpenApiDocumentTests.cs`.

## Tests

`tests/OpenApi/OpenApiDocumentTests.cs` starts the API in-process with `WebApplicationFactory`
and reads the document with the `Microsoft.OpenApi` library, the same way client generators read it.

| Test | What it checks |
|---|---|
| `Document_IsValidOpenApi31` | The document parses as OpenAPI 3.1 without errors and passes the library's validation rules |
| `Document_IsAlsoServedAsYaml` | `/openapi/v1.yaml` is served |
| `Document_DescribesEveryEndpointOfTheApplication` | Every endpoint registered in the application is in the document |
| `Operation_DocumentsAllResponses` | Each operation has a summary and exactly the expected status codes, each with a description |
| `Priority_IsDocumentedAsTheStringsTheApiSends`, `Numbers_AreDocumentedAsIntegersOnly` | Data types match the JSON the API sends |
| `DateWithCustomConverter_IsDocumentedAsDateTimeString` | `firstDueAtUtc` is documented as a `date-time` string despite its custom converter |
| `CreatedResponse_DocumentsLocationHeader`, `EveryResponse_DocumentsInstanceHeader`, `NoContentResponse_HasNoBody`, `ErrorResponses_UseProblemDetails` | Response headers, bodies and error schemas |
| `RequestBody_IsDescribedByTheRequestParameter` | Guards the `<param>` order described above |
| `Response_MatchesDocument`, `SuccessfulTodoLifecycle_MatchesDocument` | Real requests (success, `400`, `404`, `415`) return a status code, content type and required headers listed in the document |
| `UnhandledException_ReturnsDocumentedServerError` | With a failing repository the API returns the documented `500` |

Logs of these tests are written to a temp directory (`uai-zerovp-openapi-tests`), not to `src/UAI.ZeroVP.API/logs/`.

Run them with:

```bash
dotnet test --filter "FullyQualifiedName~OpenApi"
```
